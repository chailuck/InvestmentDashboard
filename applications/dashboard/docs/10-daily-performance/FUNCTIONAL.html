Daily Performance — Functional Specification

Version: 2.0  |  Last updated: 2026-07-18  |  Route: /analytics/daily-performance

1. Overview

The Daily Performance module records a point-in-time snapshot of each portfolio at the end of each trading day. Each snapshot captures three figures: the total capital deployed across all positions in the portfolio (investment), the cumulative realised profit or loss from closed positions (closed_pnl), and the unrealised profit or loss on open positions valued at the time the snapshot was taken (open_pnl). A JSONB breakdown of per-symbol open P&L is stored alongside the headline figures.

Snapshots are portfolio-scoped: one row is written per portfolio per calendar day. A user with two portfolios receives two independent snapshot rows. This replaced an earlier user-scoped model (one row per user per day) as of migration b2c3d4e5f6a7.

The module provides three user-facing capabilities:

  • A performance chart visualising investment, closed P&L, and open P&L over a date window.
  • A daily records table with inline editing so users can correct automatically computed figures.
  • A Run Now button to trigger an on-demand snapshot for today.
The page is located under the Analytics section of the dashboard at /analytics/daily-performance. It is personal — each user sees only data for their own portfolios.

2. Portfolio selector

On page load the frontend fetches GET /api/v1/portfolios. The list is stored in component state. The active portfolio is initialised to the portfolio where is_default === true; if no default exists the first portfolio in the list is selected.

  • If the user has only one portfolio the selector is not rendered — the single portfolio is used silently.
  • If the user has two or more portfolios a labelled <select> element appears in the filter bar. Changing it immediately re-fetches performance data for the newly selected portfolio.
  • All subsequent API calls (list, run, update) pass the selected portfolio_id as a query parameter.
Data fetch is guarded: if selectedPortfolioId is still null (portfolios have not loaded yet) no API call is fired. This prevents a race condition where the list endpoint is hit without a portfolio_id.

3. Date filter

The filter bar contains From and To date inputs plus five quick-select preset buttons. The default window on first load is today − 60 days to today.

PresetBehaviour

2MSets From = today − 2 months, To = today
3MSets From = today − 3 months, To = today
6MSets From = today − 6 months, To = today
1YSets From = today − 12 months, To = today

The backend enforces a hard cap: if date_to − date_from > 366 days it returns HTTP 400. The frontend does not pre-validate this; the error surfaces as an error banner.

TD-DP-07: The frontend does not check whether date_from > date_to before submitting. If a user types an invalid range, the API call will succeed with zero results rather than showing an informative error.

4. Performance chart

A custom SVG area chart renders inside a ResizeObserver-watched container so that it adapts to the available width without a page reload.

Each series is rendered as an area path (low-opacity fill) under a stroke line (full opacity). A zero-baseline line is drawn across the chart. Closed P&L and Open P&L may render below the baseline when those values are negative.

4.2 Hover tooltip

Moving the pointer over the SVG snaps to the nearest data point by dividing the inner chart width by the number of records. A crosshair line, three coloured dots, and a tooltip box appear showing:

  • The date of the selected record.
  • The investment value (blue).
  • The closed P&L value (green).
  • The open P&L value (purple).

The tooltip repositions to the left of the crosshair if it would overflow the right edge of the SVG.

4.3 Axes

  • Y axis: 5 evenly spaced tick labels. Values ≥ 1,000,000 are formatted as 1.2M; values ≥ 1,000 as 1K.
  • X axis: At most 8 labels, chosen at a uniform step across the records array. The last record always receives a label.

5. Daily records table

Below the chart a data table lists every snapshot in the date window, newest to oldest. Columns: Date, Investment, Closed P&L, Closed %, Open P&L, Open %, Open Positions.

5.1 Inline editing

The three numeric columns Investment, Closed P&L, and Open P&L are click-to-edit. Clicking a cell replaces the display value with an <input type="number"> that auto-focuses. The edit is committed on blur or Enter; Escape cancels without saving.

On commit the frontend calls PUT /api/v1/daily-performance/{date}?portfolio_id={id} with only the changed field. The backend recomputes the affected percentage column (closed_pnl_pct or open_pnl_pct) using the stored investment value. If investment itself is updated in the same request, the backend applies investment first so the new denominator is used when recomputing percentages.

5.2 Open Positions column

If a snapshot has a non-empty open_positions array, each entry is rendered as a colour-coded chip: green background and value for positive P&L, red for negative. The chip label is SYMBOL (+999). Hovering shows the percentage. If the array is null or empty, an em dash is shown.

TD-DP-08: When a portfolio has no active positions at snapshot time, open_positions is stored as NULL rather than an empty array []. Both values render identically as an em dash in the UI.

6. Run Now

The Run Now button in the page header triggers POST /api/v1/daily-performance/run?portfolio_id={id} using today as the snapshot date. The button shows a spinning icon and the label "Running…" while the request is in flight.

The operation is idempotent: if a snapshot already exists for today and the selected portfolio, it is overwritten with freshly fetched live prices and recalculated figures. Running it multiple times on the same day is safe.

After a successful run the page re-fetches the record list so the new or updated row is immediately visible in the table and chart.

7. Business rules

7.1 Investment

Sum of entry_price × position_size for all positions in the portfolio where entry_date <= snapshot_date, regardless of whether the position is open or closed.

investment = Σ (entry_price × position_size)
             for pos in portfolio_positions
             where entry_date <= snapshot_date

7.2 Closed P&L

Sum of net P&L for all positions with status = "closed" and exit_date <= snapshot_date.

for LONG:  net_pnl = (exit_price - entry_price) × position_size
for SHORT: net_pnl = (entry_price - exit_price) × position_size

closed_pnl    = Σ net_pnl over qualifying closed positions
closed_pnl_pct = (closed_pnl / investment) × 100   [0.0 when investment = 0]

7.3 Open P&L

Unrealised P&L for positions with status = "active", using a live price fetched from Yahoo Finance at snapshot time. The ticker suffix .BK is appended automatically for SET symbols.

for LONG:  pos_pnl = (current_price - entry_price) × position_size
for SHORT: pos_pnl = (entry_price - current_price) × position_size

open_pnl    = Σ pos_pnl over active positions (0.0 on price-fetch failure)
open_pnl_pct = (open_pnl / investment) × 100   [0.0 when investment = 0]

7.4 Manual corrections

A user can override any of Investment, Closed P&L, or Open P&L via inline editing. Percentage fields are recomputed server-side after every update. Manual corrections do not modify open_positions — the JSONB breakdown retains the values from the last automated or on-demand snapshot.

8. Scheduler

An APScheduler AsyncIOScheduler named _perf_scheduler fires the snapshot job every weekday (Monday–Friday) at 23:30 Bangkok time (Asia/Bangkok timezone, equivalent to 16:30 UTC). The scheduler starts unconditionally at application startup — it is not gated by any environment variable.

The job calls run_snapshot_for_all_portfolios(db, today), which iterates every portfolio across all users. Failures for individual portfolios are caught, logged, and counted; they do not abort the batch. A summary of succeeded, failed, and total counts is written to the structured log on completion.
