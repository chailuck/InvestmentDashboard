API Spec — Financial Tracker

Objective: Full CRUD for the Financial Tracker ("Tracking") feature — Tracking Sets, Categories, Sub-categories, Tracking Items, and Initial Investment Ledger entries. Served by the independent tracking-backend microservice (Phase 1: CRUD only — no "Update Tracking List" or "Dashboard" endpoints exist yet). All routes are mounted under /api/v1/tracking.
Deployment note: the Next.js proxy (frontend/src/app/api/proxy/[...path]/route.ts) does not currently route /api/v1/tracking/* requests to this service — see 18-financial-tracker/TECHNICAL.html §7.1 / §9 (TD-FT-01). The endpoints below are accurate to the running tracking-backend service reachable directly on port 8001; the browser-facing path through the frontend proxy is not yet wired to it.

Authentication

All endpoints except /health/* require Authorization: Bearer <access_token>, where the token was issued by the main backend's login endpoint. tracking-backend only verifies the token (shared APP_SECRET_KEY, same Redis blacklist) — it never issues tokens itself. See TECHNICAL.html §2 for the full verification flow.

Health

GET /api/v1/tracking/health/live

No auth. Never touches the database or Redis — always returns fast so an orchestrator cannot mistake a transient dependency blip for a dead process.

{ "status": "ok" }

GET /api/v1/tracking/health/ready

No auth. Checks Postgres (SELECT 1) and Redis (PING).

// 200 OK — both dependencies healthy
{ "status": "ok", "checks": { "database": "ok", "redis": "ok" } }

// 503 Service Unavailable — one dependency down
{ "status": "unavailable", "checks": { "database": "ok", "redis": "error: Connection refused" } }

Tracking Sets

POST /api/v1/tracking/sets

// Request
{ "name": "My Personal Finances", "description": "Household budget and net worth" }

// Response 201
{
  "id":          "b1a2c3d4-5e6f-4a7b-8c9d-0e1f2a3b4c5d",
  "name":        "My Personal Finances",
  "description": "Household budget and net worth",
  "createdAt":   "2026-08-23T09:15:00+00:00",
  "updatedAt":   "2026-08-23T09:15:00+00:00"
}
Creating a set also creates its default category/sub-category skeleton (Assets / Liabilities and their default sub-categories) in the same transaction — see TECHNICAL.html §6. The response body reflects only the created set itself; fetch GET /sets/{id}/categories afterward to see the defaults.
409 Conflict — a set with this name already exists for this user: {"detail": "A tracking set with this name already exists"}

GET /api/v1/tracking/sets

Returns the caller's Tracking Sets, ordered by createdAt ascending.

[
  { "id": "...", "name": "My Personal Finances", "description": null, "createdAt": "...", "updatedAt": "..." },
  { "id": "...", "name": "Family Trust",          "description": null, "createdAt": "...", "updatedAt": "..." }
]

GET /api/v1/tracking/sets/{id}

404 Not Found — set does not exist or belongs to another user: {"detail": "Tracking set not found"}

PUT /api/v1/tracking/sets/{id}

// Request — both fields optional; only provided fields are updated
{ "name": "My Finances (2026)", "description": null }

// Response 200 — updated set
404 Not Found — set not found.
409 Conflict — the new name collides with another of your sets.

DELETE /api/v1/tracking/sets/{id}

Hard delete. Cascades to every category, sub-category, tracking item, and ledger entry beneath the set. Returns HTTP 204 No Content.

404 Not Found — set not found.

  "type":                       "Bank account",

Initial Investment Ledger

Ledger endpoints (POST/GET .../entries, GET .../running-total) are gated at the application layer: the target Tracking Item's initialInvestmentTracking flag must already be true, or these endpoints reject the call with 400 — even though the underlying ft_initial_investment_entry table has no DB-level constraint tying it to the flag.

POST /api/v1/tracking/items/{itemId}/entries

// Request — amount must be non-zero; positive = increase, negative = decrease
{ "amount": 50000.00, "entryDate": "2026-01-15" }

// Response 201
{
  "id":              "f5a6b7c8-...",
  "trackingItemId":  "e4d5f6a7-...",
  "amount":          50000.00,
  "entryDate":       "2026-01-15",
  "createdAt":       "2026-08-23T09:30:00+00:00",
  "updatedAt":       "2026-08-23T09:30:00+00:00"
}
400 Bad Request — item does not have initialInvestmentTracking enabled: {"detail": "This tracking item does not have initial_investment_tracking enabled; enable it before adding ledger entries"}
404 Not Found — item not found.
422 Unprocessable Entity — amount is zero: "amount must not be zero (positive = increase, negative = decrease)"

GET /api/v1/tracking/items/{itemId}/entries

Ordered by entryDate ascending, then createdAt ascending for same-day entries.

404 Not Found — item not found.
