API Spec — Financial Tracker

Objective: Full CRUD for the Financial Tracker ("Tracking") feature — Tracking Sets, Categories, Sub-categories, Tracking Items, Initial Investment Ledger entries (Phase 1); Update Tracking Lists with read-time balance deltas (Phase 2); a read-only quarterly/yearly balance-grid rollup report (Phase 3); and a full-snapshot export endpoint (Phase 4) used by the Dashboard page's "Email Dashboard" button. Phase 5 (ADR-018) adds an optional note on ledger entries, a profitVsOriginal block on the running-total response, and a per-set "profit vs original investment" rollup endpoint. Phase 7 (ADR-020–ADR-025) adds the BOND tracking-item type, a standalone bond-register resource (5 endpoints) whose status is computed on every read, and optional code / name labels on ledger entries. Configurable Item Types (ADR-027) replaces the closed 7-value type string with an admin-managed ft_item_type registry: a new /tracking/item-types resource (7 endpoints — GET for any tracker user, the rest admin-only), item create/update switch from type to typeId, and item / dashboard / export responses gain an embedded item-type object plus a stable typeSlug. Served by the independent tracking-backend microservice. All routes are mounted under /api/v1/tracking.
Scope note: this file covers only endpoints served by tracking-backend. The Phase 4 "Email Dashboard" feature also added a new endpoint on the separate main backend service (POST /api/v1/email/send-export) — that endpoint is documented in 18-financial-tracker/TECHNICAL.html §12.2/§12.3 instead, since no standalone API reference page exists anywhere in this docs tree for any main-backend /email/* endpoint (a pre-existing gap, not one introduced by this feature — see TECHNICAL.html §12.6).
Deployment note: the Next.js proxy (frontend/src/app/api/proxy/[...path]/route.ts) does not currently route /api/v1/tracking/* requests to this service — see 18-financial-tracker/TECHNICAL.html §9.1 / §11 (TD-FT-01). The endpoints below are accurate to the running tracking-backend service reachable directly on port 8001; the browser-facing path through the frontend proxy is not yet wired to it.

Authentication

All endpoints except /health/* require Authorization: Bearer <access_token>, where the token was issued by the main backend's login endpoint. tracking-backend only verifies the token (shared APP_SECRET_KEY, same Redis blacklist) — it never issues tokens itself. See TECHNICAL.html §2 for the full verification flow.

(Configurable Item Types / ADR-027) The mutating /tracking/item-types routes additionally require an admin caller: the require_admin dependency runs the same verify + jti + blacklist path, then requires the signed JWT role claim == "admin" (else 403). No users-table lookup — the role is read straight from the token. GET /tracking/item-types is open to any authenticated tracker user.

Item Types (Configurable Item Types / ADR-027)

The admin-managed registry that replaces the old closed 7-value type enum. Implemented in app/api/v1/endpoints/item_types.py; model app/models/item_type.py; schemas app/schemas/item_type.py; the fixed capability set is app/services/item_type_capabilities.py. GET is any authenticated tracker user; every mutating route requires require_admin (signed JWT role == "admin", no users-table access). Error bodies follow this service's {"detail": "..."} convention; the status codes are the contract. Behaviour: FUNCTIONAL.html §17; design: TECHNICAL.html §17 and 20-item-type-config/DESIGN.html.

ItemType response shape

{
  "id":         "22222222-2222-4222-8222-222222222222",
  "slug":       "property",          // immutable, code-facing key — never editable
  "label":      "Property",          // admin-editable human name
  "sortOrder":  1,
  "isSystem":   true,                // built-in; archive-only, capabilities locked
  "isArchived": false,
  "capabilities": ["counts_as_property"],   // subset of { counts_as_property, bond_register }
  "itemCount":  12,                  // ONLY on GET /item-types; null/absent elsewhere
  "createdAt":  "2026-09-06T12:00:00+00:00",
  "updatedAt":  "2026-09-06T12:00:00+00:00"
}
  • Capabilities are a fixed, code-owned set of exactly two keys. counts_as_property — items of this type feed propertyBreakdown.propertyTotal and the Analysis Property lens; admin-assignable to a custom type, locked-on for the built-in Property type. bond_register — unlocks the bond register (see Bonds); system-only, never grantable via any endpoint (rejected with 422).
  • slug is generated once from the label at create ([a-z0-9_], _2/_3… on collision) and is never accepted or changed on any write — sending slug in a create/update body is a 422.

Initial Investment Ledger

Ledger endpoints (POST/GET .../entries, GET .../running-total) are gated at the application layer: the target Tracking Item's initialInvestmentTracking flag must already be true, or these endpoints reject the call with 400 — even though the underlying ft_initial_investment_entry table has no DB-level constraint tying it to the flag.

POST /api/v1/tracking/items/{itemId}/entries

// Request — amount must be non-zero; positive = increase, negative = decrease.
// note (Phase 5) is optional: max 500 chars; blank/whitespace-only is stored as null; Thai text kept verbatim.
// code, name (Phase 7) are optional: max 100 chars each; blank/whitespace-only -> null; Thai kept verbatim.
{ "amount": 50000.00, "entryDate": "2026-01-15", "note": "annual top-up", "code": "TH0623A", "name": "5Y govvy tranche" }

// Response 201
{
  "id":              "f5a6b7c8-...",
  "trackingItemId":  "e4d5f6a7-...",
  "amount":          50000.00,
  "entryDate":       "2026-01-15",
  "note":            "annual top-up",
  "code":            "TH0623A",
  "name":            "5Y govvy tranche",
  "createdAt":       "2026-08-23T09:30:00+00:00",
  "updatedAt":       "2026-08-23T09:30:00+00:00"

The profitVsOriginal object (Phase 5)

Always present on the response — it compares this item's cost basis against its latest recorded balance. Produced by the shared profit_math.compute_profit helper (TECHNICAL.html §13.2), so the null rules below match those of the set-wide rollup endpoint.

FieldTypeNotes
netOriginalInvestmentnumber, nullableRunning signed sum of every ledger entry amount for this item (same value as currentTotal). null only when the item has no entries at all.
currentValuenumber, nullableThe item's balance in its most-recent populated (year, quarter) slot, using the same winning-Update-Tracking-List selection as the Dashboard balance grid. null when the item has never had a balance recorded on any Update Tracking List.
currentValueSlot{year, quarter}, nullableWhich slot currentValue came from; null whenever currentValue is null.
profitnumber, nullablecurrentValue - netOriginalInvestment; null unless both inputs are present.
profitPercentnumber, nullableprofit / netOriginalInvestment * 100, only when netOriginalInvestment > 0 and currentValue exists. When the net is 0 or negative, profit is still populated but profitPercent is null — never Infinity, NaN, or a string.

Bonds (Phase 7)

A standalone register of individual bond holdings, each attached to a Tracking Item whose type carries the bond_register capability (ADR-027 — the built-in BOND type; the gate is capability-based, not a label match, so a renamed bond type still works). Implemented in app/api/v1/endpoints/bonds.py; schemas in app/schemas/bond.py; status logic in app/services/bond_status.py. The router carries no prefix — its routes span /items/{itemId}/bonds (collection under an item) and /bonds/{bondId} (single bond by id), the same shape the ledger feature uses across tracking_items.py + entries.py. Standalone by design (ADR-024): bonds do not appear in the Dashboard balance grid, the Update Tracking Lists, the original-investment rollup, the export snapshot, or the Analysis view. See 18-financial-tracker/FUNCTIONAL.html §15 and 18-financial-tracker/TECHNICAL.html §15 (ADR-020–ADR-025).

Wire-format conventions

  • camelCase keys, like the rest of this API: trackingItemId, startDate, expiredDate, createdAt, updatedAt.
  • amount is a JSON string (e.g. "100000.0000") — every Decimal in this API is serialised as a string. It is quantized to 4 decimal places on write by the NUMERIC(19,4) column: excess precision is silently rounded (half away from zero), not rejected.
  • status is a computed string enum — "Pre-order" | "Active" | "Expire" | "Unknown" — present on every bond read, never accepted on write and never stored. It is derived on every read from startDate / expiredDate versus the current date in Asia/Bangkok: Unknown if either date is missing; Pre-order if today < start; Active if start ≤ today ≤ expired (both bounds inclusive); Expire if today > expired. All bonds in a list response are evaluated against one "today" captured once for that response.
  • interestRate (Phase 7 enh. — ADR-026) is an optional stored annual rate entered as a percent — "3.2500" means 3.25% p.a. JSON string like every other Decimal (or null). Allowed range 0–100 inclusive; 4 dp, excess precision rounded on write.
  • years (Phase 7 enh. — ADR-026) is a computed integer (bare JSON number, or null) — round_half_up((expiredDate - startDate).days / 365.25). Present on every bond read; never accepted on write, never stored. null when either date is missing; not clamped for inverted dates (can be 0 or negative). See §16 of 18-financial-tracker/TECHNICAL.html.
  • Dates are ISO YYYY-MM-DD strings or null.

Original Investment vs Profit (Phase 5)

A read-only rollup that pairs each tracked item's original invested amount (the signed sum of its Initial Investment Ledger entries) with its current balance (its latest recorded Update Tracking List balance), for the whole tracking set at once. Implemented in app/api/v1/endpoints/dashboard.py alongside the Phase 3 balance-grid route; profit math is the shared app/services/profit_math.py — compute_profit(); the set-wide assembly is app/services/original_investment_rollup.py. No request body, no query parameters beyond the path's setId; nothing is written or cached. See 18-financial-tracker/FUNCTIONAL.html §12.13 and 18-financial-tracker/TECHNICAL.html §13.

GET /api/v1/tracking/sets/{setId}/dashboard/original-investment

Definitions

  • Net original investment — running signed sum of every ledger entry amount for the item. null (render "—", never 0) when the item has no entries.
  • Current value — the item's balance in its most-recent populated (year, quarter) slot, from the same winning-list selection the balance grid uses. null when the item has never had a recorded balance.
  • Profit — currentValue - netOriginalInvestment; null unless both are present.
  • Profit % — profit / netOriginalInvestment * 100, only when netOriginalInvestment > 0 and a current value exists; otherwise null (the profit amount is still shown). Never Infinity / NaN.
  • Covered — flag on AND at least one entry AND a current value exists. Does not require a positive net.

Scope

items[] and coverage.totalCount (M) include every non-exclusive item in the set with initialInvestmentTracking = true — covered items and not-yet-covered items alike (the latter with null numeric fields). Items with the flag off, and exclusive items, are excluded entirely — never a row, never in a total. coverage.shownCount (N) is the covered count; coverage.excludedItemNames lists the in-scope items that are not covered. totals aggregate covered items only; totals.profitPercent is null when the summed net is 0 or negative.

Export (Phase 4)

A single read-only endpoint returning a full, restorable snapshot of one Tracking Set — every Category, Sub-category, Tracking Item, Update Tracking List, Update Tracking List balance, and Initial Investment Ledger entry it contains, as raw fields with no derived or calculated values. Implemented in app/api/v1/endpoints/export.py; schemas in app/schemas/export.py. This is the JSON backup attached to the email sent by the Dashboard page's "Email Dashboard" button. See 18-financial-tracker/FUNCTIONAL.html §13 for user-facing behaviour and 18-financial-tracker/TECHNICAL.html §12.1 for the ownership and query-scoping detail. (Phase 5) exportVersion is now 2: initialInvestmentEntries[] rows carry the new optional note field.

GET /api/v1/tracking/sets/{setId}/export

No request body, no query parameters beyond the path's setId. Nothing is ever written by this endpoint. Every returned row is scoped both by the FK chain down from the verified tracking set AND by an explicit user_id filter on every query (belt-and-suspenders, since this response is intended for later re-import).
