API Spec — Backup & Restore

Objective: Full-database backup and restore over the shared investment_db database, plus per-table pipe-separated (PSV) export/import. The covered table set and a foreign-key-safe order are discovered from the live PostgreSQL catalogue on every call — there is no hard-coded table list, so tables added by future migrations in either the backend or the tracking-backend service (ft_*) are covered automatically. All endpoints are admin only (require_admin). Backup file format is v2.0 (gzip JSON); pre-2.0 files still restore in a legacy mode.

Design detail: 19-backup-restore/TECHNICAL.html · Operations: Runbook · UX: Functional spec.
Source: backend/app/api/v1/endpoints/backup.py, backend/app/services/backup/__init__.py, backend/app/schemas/backup.py.

POST /api/v1/backup/create

Discovers every table, exports each covered table, and writes backup_<UTC ts>.json.gz to BACKUP_DIR with mode 0o600. Retention then trims to the newest BACKUP_RETENTION files (default 7). Holds pg_advisory_xact_lock so it cannot run concurrently with a restore. Read-only on the database — does not require a superuser role.

Request

No body.

Response 200

{
  "filename": "backup_20260901_021407.json.gz",
  "created_at": "2026-09-01T02:14:07.512+00:00",
  "size_kb": 84.6,
  "total_rows": 5123,
  "version": "2.0",
  "covered_tables": ["users", "action_plans", "purchase_plan_items", "...", "ft_bond"],
  "row_counts": { "users": 4, "action_plans": 12, "ft_bond": 7 },
  "checksums": { "users": "sha256:1f3b...", "action_plans": "sha256:9ac2..." }
}

covered_tables is in foreign-key-safe insert order. The schema-version tables (alembic_version, ft_alembic_version) are not in covered_tables; they are captured inside the file under schema_versions / excluded_tables (see File format v2.0).

curl

curl -sS -X POST https://<host>/api/v1/backup/create \
  -H "Authorization: Bearer $ADMIN_TOKEN"

GET /api/v1/backup/tables

The authoritative “what does a backup cover” list. Feeds the frontend coverage card and the PSV table selector (which hides rows with restorable: false). Bounded by statement_timeout = 30s.

Response 200

  "total_tables": 30,
  "insert_order": ["users", "action_plans", "...", "ft_bond", "alembic_version", "ft_alembic_version"],
  "tables": [
    { "name": "users",              "row_count": 4,   "owner_service": "backend",          "restorable": true,  "in_conflict_check": true },
    { "name": "ft_bond",            "row_count": 7,   "owner_service": "tracking-backend", "restorable": true,  "in_conflict_check": true },
    { "name": "alembic_version",    "row_count": 1,   "owner_service": "backend",          "restorable": false, "in_conflict_check": false,
      "note": "schema-version table; managed by Alembic migrations, never restored" },
    { "name": "ft_alembic_version", "row_count": 1,   "owner_service": "tracking-backend", "restorable": false, "in_conflict_check": false,

FieldMeaning
owner_service"tracking-backend" for ft_* tables, else "backend".
restorablefalse only for the two schema-version tables — they are never written by a restore.

Streams the stored file as application/gzip. filename is validated by _resolve_backup_path (see invalid-filename).

Responses

  • 400 urn:backup:error:invalid-filename.
  • 404 urn:backup:error:not-found.

Permanently deletes one stored backup file.

Response 200

Errors: 400 invalid-filename, 404 not-found.

POST /api/v1/backup/restore/{filename}

Restores from a stored backup file. Serialised against create/other restores by an advisory lock; the whole operation is one transaction. Requires a superuser-capable DB role (insufficient-privilege).

Request body (optional — application/json)

{
  "mode": "skip_if_conflict",   // "skip_if_conflict" (default) | "replace_all"
  "confirm": "REPLACE ALL DATA"  // REQUIRED verbatim when mode = "replace_all"
}
modeBehaviour
skip_if_conflict
(default)		Pre-write check: SELECT 1 ... LIMIT 1 on every covered table. If any is non-empty → rollback + 409, nothing written. Otherwise load all covered tables and commit.
replace_allRequires confirm == "REPLACE ALL DATA". TRUNCATE ... CASCADE covered∩live tables in reverse FK order, reload, single transaction. Any row failure → full rollback + 422.

On both modes: tables in the DB but absent from the file are left untouched; the schema-version tables are never written (drift is reported instead).

Response 200 — RestoreResult

{
  "version": "2.0",
  "mode": "skip_if_conflict",
  "legacy_backup": false,
  "restored": { "users": 4, "action_plans": 12, "ft_bond": 7 },
  "total_rows": 5123,
  "errors": [],
  "covered_tables": ["users", "action_plans", "...", "ft_bond"],
  "uncovered_tables": [],
  "file_tables_not_in_db": [],
  "checksum_verification": { "users": "ok", "action_plans": "ok" },
  "schema_version_drift": {
    "alembic_version":    { "file": "d4e5f6a7b8c9", "live": "d4e5f6a7b8c9", "match": true },
    "ft_alembic_version": { "file": "00f7a890545d", "live": "00f7a890545d", "match": true }
  },
  "source_created_at": "2026-09-01T02:14:07+00:00"
}
FieldMeaning
restoredRows loaded per table.
checksum_verificationPer table: ok | mismatch (file edited post-backup) | skipped (no checksum, e.g. legacy).
schema_version_driftPer schema-version table: file vs live version_num and whether they match. Informational — nothing is written to these tables.
uncovered_tablesLive tables not present in this backup (left untouched).
file_tables_not_in_dbTables in the file with no matching live table.
legacy_backup / mode:"legacy"Set when a pre-2.0 file was restored.

curl

# Safe restore into an empty DB
curl -sS -X POST "https://<host>/api/v1/backup/restore/backup_20260901_021407.json.gz" \
  -H "Authorization: Bearer $ADMIN_TOKEN" -H "Content-Type: application/json" \
  -d '{"mode":"skip_if_conflict"}'

# Destructive replace
curl -sS -X POST "https://<host>/api/v1/backup/restore/backup_20260901_021407.json.gz" \
  -H "Authorization: Bearer $ADMIN_TOKEN" -H "Content-Type: application/json" \
  -d '{"mode":"replace_all","confirm":"REPLACE ALL DATA"}'

Error responses

  • 400 bad-mode, unsupported-version, invalid-file, confirm-required, invalid-filename
  • 404 not-found
  • 409 target-not-empty — body carries conflicting_tables: [{table, row_count}], mode, and legacy_backup when applicable
  • 422 unknown-column (errors list), restore-failed (errors list — full rollback)
  • 500 insufficient-privilege

POST /api/v1/backup/restore/upload

Same restore engine, from an uploaded file. The gzip is decompressed with a hard cap of BACKUP_MAX_UNCOMPRESSED_BYTES (default 200 MiB) → 413 urn:backup:error:too-large on exceed.

Request — multipart/form-data

Part / paramWhereNotes
filemultipart bodyThe .json or .json.gz backup. Gzip is detected by magic bytes or a .gz name.
modequery stringskip_if_conflict (default) | replace_all
confirmquery stringREPLACE ALL DATA (URL-encoded) when mode=replace_all
curl -sS -X POST "https://<host>/api/v1/backup/restore/upload?mode=replace_all&confirm=REPLACE%20ALL%20DATA" \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -F "file=@backup_20260901_021407.json.gz"

Responses: as POST /restore/{filename}, plus 413 urn:backup:error:too-large (body has limit_bytes) and 400 invalid-file for a non-object / unparseable payload.

GET /api/v1/backup/export-table/{table}

Exports one table as a pipe-separated (PSV) file: text/plain attachment named <table>_<YYYYMMDD_HHMMSS>.psv. Line 1 is the header (column names); each following line is a row. Empty field = NULL; dict/list values are JSON; a literal | is escaped \| and a newline \n.

Errors

  • 400 urn:backup:error:schema-version-table — table is alembic_version / ft_alembic_version.
  • 400 urn:backup:error:unknown-identifier — not a live table.
curl -sS -OJ "https://<host>/api/v1/backup/export-table/users" \
  -H "Authorization: Bearer $ADMIN_TOKEN"

POST /api/v1/backup/import-table/{table}

Imports a PSV file into one table. Column identifiers are validated against information_schema.columns for the real table and quoted; values are positional bind parameters. Runs under session_replication_role = replica in one transaction.

Request — multipart/form-data

Part / paramWhereNotes
filemultipart bodyPSV file (header row + ≥ 1 data row).
modequery stringappend (default) → INSERT ... ON CONFLICT DO NOTHING. replace → TRUNCATE ... CASCADE first.
confirmquery stringRequired == "REPLACE <table>" when mode=replace.

Response 200

{ "imported": 42, "table": "users", "mode": "append" }

Errors

  • 400 schema-version-table, unknown-identifier, confirm-required, invalid-file (fewer than 2 lines).
  • 422 unknown-column (body has columns), import-failed (transaction rolled back).
curl -sS -X POST "https://<host>/api/v1/backup/import-table/users?mode=replace&confirm=REPLACE%20users" \
  -H "Authorization: Bearer $ADMIN_TOKEN" -F "file=@users_20260901_021407.psv"

Backup file format v2.0

A backup is a gzip-compressed JSON object.

{
  "version": "2.0",
  "created_at": "2026-09-01T02:14:07.512+00:00",
  "created_by": "3f9b1c2a-...",              // admin user UUID
  "source_db": "investment_db",
  "generator": "backend/backup@2.0",
  "covered_tables": ["users", "...", "ft_bond"],   // FK-safe insert order
  "insert_order":   ["users", "...", "ft_bond"],   // == covered_tables; TRUNCATE order is the reverse
  "excluded_tables": {
    "alembic_version":    "schema-version table; owned by Alembic migrations, never restored",
    "ft_alembic_version": "schema-version table; owned by Alembic migrations, never restored"
  },
  "row_counts": { "users": 4, "...": 0 },
  "checksums":  { "users": "sha256:1f3b...", "...": "sha256:..." },
  "schema_versions": {
    "alembic_version":    [ { "version_num": "d4e5f6a7b8c9" } ],
    "ft_alembic_version": [ { "version_num": "00f7a890545d" } ]
  },
  "tables": {
    "users": [ { "id": "...", "email": "...", "hashed_password": "...", "role": "admin", ... } ],
    "...":   [ ... ]
    // NOTE: alembic_version / ft_alembic_version are NOT here — only in schema_versions
  }
}

Value normalisation (one serialiser for the payload AND the checksum)

Python typeOn disk
UUIDstring
datetime / dateISO-8601 string
Decimalfloat
bytesbase64 ASCII string

Checksum

checksums[t] = "sha256:" + sha256( "\n".join( sorted(
                 json.dumps(row, sort_keys=True, default=<normaliser>) for row in rows[t] ) ) )
The checksum is computed over the normalised shape that lands in the file, so a restore recomputes an identical digest. It therefore detects post-backup modification of the file, not fidelity to the source database (the Decimal → float step can round a high-precision numeric invisibly).

Legacy & unsupported versions

  • A file whose version is "1.0", "1.1" or absent — or which lacks covered_tables / checksums — restores in legacy mode: result carries legacy_backup: true, mode: "legacy", uncovered_tables, and checksum_verification all "skipped". The conflict / confirm policy is identical to v2.0.
  • A version that is a non-empty string but neither "2.0" nor a known legacy value → 400 urn:backup:error:unsupported-version, before any work.
